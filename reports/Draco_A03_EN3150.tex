\section{Introduction}
Running image classifiers at the edge requires a balance between recognition accuracy and the memory and computation available on the target device. In this assignment, we investigate that balance using the five-class DeFungi dataset. We first develop two custom convolutional neural networks (CNNs) under the specified parameter budget, then compare them with fine-tuned MobileNetV2 and ShuffleNetV2 1.0x. To make the results comparable, all final evaluations use the corrected, leakage-free dataset split and the clean-split Stage 2 experiments.

The reported measurements were checked against saved JSON and CSV summaries, classification reports, training histories, checkpoints, and profiler outputs using \texttt{scripts/generate\_report\_data.py}. All seven experiments record the same package SHA-256 and manifest SHA-256 in their JSON metadata, and their training histories each cover 20 epochs. Each final confusion matrix contains \DatasetTest{} test images. This provides a consistent basis for the model comparisons without using any values from the earlier contaminated split.

\textbf{Computational measurement.} For an input of $1\times3\times64\times64$, we count multiply-accumulate operations (MACs) in Conv2d and Linear layers. BatchNorm, activations, pooling, residual additions, concatenation, channel shuffle, softmax, and data movement are excluded. FLOPs are calculated as $2\times$ MACs throughout the report. These figures describe arithmetic workload, not measured inference time on a physical device.

\section{Task 1: Data Preparation}
\subsection{Corrected common split}
The UCI DeFungi dataset contains five classes: H1, H2, H3, H5, and H6. All images in the prepared package are RGB and have a resolution of exactly $64\times64$ pixels. Before dividing the data, we checked for duplicate content in two ways: SHA-256 hashes of the original files and SHA-256 hashes of the decoded pixel arrays. This identifies both byte-identical files and images with identical pixel content despite possible file-level differences. We then performed a deterministic, class-aware allocation, keeping every member of each identical-content group in the same split. This prevents the model from being evaluated on a duplicate of an image it saw during training.

\section{Task 2: Custom Architecture Design}
\subsection{Model A: standard CNN}
Model A serves as the conventional CNN baseline. It has four feature-extraction blocks, each consisting of a standard $3\times3$ convolution, BatchNorm, ReLU, and $2\times2$ max pooling. As the spatial dimensions decrease, the channel count increases to capture richer features. The implemented layers and their parameter counts are detailed in Table~2.

For a biased Conv2D layer,
\[
P_{\mathrm{conv}}=(K_hK_wC_{\mathrm{in}}C_{\mathrm{out}})+C_{\mathrm{out}},
\]
and trainable BatchNorm contributes $2C_{\mathrm{out}}$ parameters (scale and shift). For example, Block 1 has $(3\cdot3\cdot3\cdot32)+32=896$ convolution parameters and $2\cdot32=64$ BatchNorm parameters. The four blocks total 389,376 parameters. The classifier contributes
\[
(4096\cdot512+512)+(512\cdot128+128)+(128\cdot5+5)=2,163,973.
\]
Therefore the verified total is $389,376+2,163,973=\mathbf{\ModelAParams}$ trainable parameters.

After every convolutional BatchNorm layer and after the first two fully connected layers, Model A uses ReLU. Unlike sigmoid and tanh, ReLU only requires a simple threshold operation and avoids exponential evaluations. This is an attractive property for resource-limited hardware, although actual device latency was not measured in this study.

\subsection{Model B: depthwise-separable CNN}
To explore a more compact design, Model B replaces most standard convolutions with depthwise-separable operations. A standard convolutional stem is followed by six depthwise-separable blocks, global average pooling (GAP), dropout, and a linear classifier. Within each block, depthwise Conv2D, BatchNorm, and ReLU6 are followed by pointwise Conv2D, BatchNorm, and ReLU6. Separating spatial filtering from channel mixing reduces the parameter and arithmetic demands of the feature extractor.

The depthwise and pointwise convolution parameter formulas are
\[
P_{\mathrm{DW}}=K_hK_wC_{\mathrm{in}} \quad\text{and}\quad
P_{\mathrm{PW}}=C_{\mathrm{in}}C_{\mathrm{out}},
\]
because both use \texttt{bias=False}. Their BatchNorm terms are $2C_{\mathrm{in}}$ and $2C_{\mathrm{out}}$. Thus a complete block has
\[
P_{\mathrm{block}}=9C_{\mathrm{in}}+2C_{\mathrm{in}}+C_{\mathrm{in}}C_{\mathrm{out}}+2C_{\mathrm{out}}.
\]
For Block 1 this is $144+32+512+64=752$. For Block 2, whose output width is also 32, it is $288+64+1024+64=1,440$. The stem has $3\cdot16\cdot9+2\cdot16=464$ parameters and the classifier has $128\cdot5+5=645$. Summing every row gives:
\[
\boxed{\text{Model B trainable parameters}=\ModelBParams<100,000.}
\]

The arithmetic benefit can also be seen analytically. Considering convolution alone, the ratio between depthwise-separable and standard convolution is $1/C_{\mathrm{out}}+1/9$. For both the 16-to-32 and 32-to-32 blocks, this corresponds to 14.24\%; the ratio becomes smaller for the 64- and 128-output blocks. As with all MAC calculations in this report, the comparison excludes BatchNorm and activation operations.

ReLU6 is applied after the stem and after both convolution stages in every separable block. It retains ReLU's simple piecewise-linear behavior while adding an upper clamp, without requiring exponential functions. At the output, a strictly linear layer produces five logits for \texttt{CrossEntropyLoss}; applying ReLU6 or softmax at that point would change the intended loss interface, so neither is included.

\section{Task 3: Optimizer Selection and Tuning}
\subsection{Controlled comparison}
We compared three optimizers on Model B to understand how the update rule affects convergence. For a fair comparison, all three trials shared the corrected dataset split, the same initial-state hash, seed 42, batch size 32, augmentation settings, cross-entropy loss, and weight decay $10^{-4}$. Training lasted 20 epochs in each case, and the checkpoint with the highest validation accuracy was selected. We also applied \texttt{ReduceLROnPlateau} to validation loss with a reduction factor of 0.5 and patience 4; none of these runs reached a point where the scheduler reduced the learning rate.

\subsection{Momentum effect}
Momentum accumulates a velocity in directions supported by successive gradients:
\[
v_t=\mu v_{t-1}+g_t,\qquad \theta_{t+1}=\theta_t-\eta v_t.
\]
By carrying information from previous gradients into the next update, momentum can reduce oscillations and help the optimizer move more steadily in directions where the gradient is consistent. The measured curves reflect this advantage. At epoch 10, SGD with momentum reached \MomentumEpochTenVal\% validation accuracy, compared with \SGDEpochTenVal\% for standard SGD. It also achieved a higher best validation accuracy (\MomentumBestVal\% versus \SGDBestVal\%), a lower final validation loss (\MomentumFinalValLoss{} versus \SGDFinalValLoss), and better test accuracy (\MomentumTestAccuracy\% versus \SGDTestAccuracy\%).

\subsection{Why Adam and learning rate 0.001 were selected}
Adam gave the strongest results within the same 20-epoch training budget, with \AdamBestVal\% best validation accuracy, \AdamTestAccuracy\% test accuracy, and macro F1 \AdamFOne. These results were higher than those of either SGD variant. The learning curves also show continued progress: validation accuracy reached \AdamEpochTenVal\% by epoch 10, and its best checkpoint occurred at epoch \AdamBestEpoch. Adam combines a first-moment estimate, similar in purpose to momentum, with second-moment scaling to adjust the effective update size for each parameter. This can make training less sensitive to differences in gradient magnitude across layers.

We therefore retained Adam with a base learning rate of 0.001, rather than the 0.01 used in both SGD trials. The smaller nominal rate works with Adam's adaptive scaling to support steady updates; in the actual run, it produced decreasing training and validation losses and the highest validation accuracy. Although a plateau scheduler was enabled, it did not lower the learning rate, so every recorded Adam epoch used 0.001. The optimizer choice is based on this controlled comparison, not on an assumption that Adam is always superior.

\subsection{Model A versus Model B trade-off}
Despite its much smaller size, Model B improved test accuracy by \ModelBAccuracyGainVsA{} percentage points and achieved a higher macro F1 (\ModelBFOne{} versus \ModelAFOne). It requires \ModelBParamReductionVsA\% fewer parameters---equivalent to \ModelBParamFactorVsA$\times$ fewer---and \ModelBMACReductionVsA\% fewer calculated MACs. The checkpoint is also substantially smaller: \ModelBSizeKiB\ KiB rather than \ModelASizeMiB\ MiB. In our training environment, its average epoch was shorter as well.

Model A remains a useful reference because its standard convolutions and large fully connected classifier are familiar and offer substantial representational capacity. However, that extra capacity did not translate into better accuracy on the clean test set. Model B's depthwise-separable layers and global pooling offer a more attractive balance for resource-constrained exploration. This finding should not be confused with a deployment guarantee: checkpoint size, parameter count, MACs, activation RAM, and inference latency describe different aspects of cost. We did not measure peak device RAM or inference latency.

\section{Task 5: Lightweight Pre-trained Models}

For this task, we evaluated the checkpoint with the lowest validation loss.

Model B thus offers the lowest calculated arithmetic cost among these three models. The pre-trained alternatives spend more computation in exchange for better recognition, drawing on different efficient network blocks, greater capacity, and features learned from ImageNet. MAC ratios are useful for comparing workloads, but they are not direct predictions of device latency.

\subsection{Engineering recommendations}
\begin{itemize}[leftmargin=*]
\item \textbf{Strictest parameter, storage, or arithmetic budget: Model B.} It is trained from scratch, contains only \ModelBParams{} parameters, and has the smallest checkpoint and MAC count. Quantization, peak-RAM profiling, operator support, and on-device latency must still be measured.
\item \textbf{Balanced accuracy and resource cost: ShuffleNetV2 1.0x.} It reaches \ShuffleAccuracy\% accuracy with substantially fewer parameters, checkpoint storage, and MACs than MobileNetV2.
\item \textbf{Accuracy-first choice: MobileNetV2.} It reaches \MobileAccuracy\% accuracy and macro F1 \MobileFOne, the strongest measured classification result, with the highest compute cost among the three final candidates.
\end{itemize}

\section{Conclusion}
The experiments demonstrate that a carefully designed lightweight CNN can outperform a much larger conventional baseline. On the leakage-free split, Model B gives better classification results than Model A with \ModelBParamReductionVsA\% fewer parameters and \ModelBMACReductionVsA\% fewer MACs. Fine-tuned MobileNetV2 and ShuffleNetV2 achieve considerably higher accuracy, but this comes with increased resource requirements and reflects differences in architecture, capacity, and ImageNet pre-training.

For an edge application, the preferred model therefore depends on the actual accuracy target and limits on storage, RAM, latency, and energy. Our measurements cover checkpoint storage and training time, and our calculations estimate MACs; peak microcontroller RAM consumption and on-device inference latency remain to be tested before deployment.
